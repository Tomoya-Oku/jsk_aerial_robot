# 実験計画と評価

本書は未完了の研究実験の計画。モデル・単体テストや過去の別構成の動作確認を、操作者実験・実飛行の完了とは扱わない。
各機能の現在の対応範囲は[ソフトウェア設計](software.md#現行実装)、準備項目は[残作業](roadmap.md)を参照する。

## 共通条件

- 対象機は4リンク・内部6自由度のDRAGON。既存飛行制御器、LiDAR、カメラを利用する。
- 操作者は座位で右腕Mk-IIとJoystickを使用し、機体映像・形状を確認する。
- 必要に応じてOptiTrackと6軸F/Tセンサを評価用Ground Truthに使う。
  OptiTrackを操作者へのナビゲーション情報にはしない。
- シミュレーション、係留等の安全な環境、実飛行の順に検証する。
  危険なfilter OFF条件を実機で無理に実施しない。

## 実験1：写像方式の比較

修論の片腕・両腕それぞれについて関節角方式と中心線方式を、同じ機体・feasibility条件で比較する。
関節座標・体幹点・固定軸合わせ・両腕の基準姿勢を実測校正してから比較する。
Straight、L-shape、S-shape、3D bend、狭隘通過用の代表形状を連続的に生成する。

評価は正規化形状RMSE、DRAGON関節空間のcoverage、目標形状の達成時間、関節速度RMSE、
位相遅れ、end-to-end latency、対応の分かりやすさ、NASA-TLX。
安全条件を固定し、写像方式自体の差を評価する。

## 実験2：飛行可能性を考慮した形態操作

Human mapping単独とfeasibility処理を加えた条件を主にシミュレーションで比較する。
人間形状の保持と飛行可能性の両立を調べる。
現在のholdゲートによる拒否と、今後実装する形態補正を別条件として記録する。

評価はHuman–Robot形状誤差、\(f_{min}\)、\(\tau_{min}\)、推力飽和率、
関節トルク制約違反、特異・実現不能状態の回数、位置・姿勢追従誤差。
形態候補、発行指令、実関節角、ゲート拒否をログで区別する。

## 実験3：LiDARを利用した狭隘通過

操作者が映像で進行方向を決め、腕で形態を生成して開口部を通過する。
mapping単独とLiDAR局所衝突制約を加えた条件を比較する。
条件数を抑える場合は、写像比較で選定した1方式に固定する。

評価は成功率、完了時間、衝突回数、最小クリアランス、形状誤差、
optimizerによる修正量、飛行可能性余裕、NASA-TLX。

## 実験4：狭隘通過と高トルク作業の統合

タスクは「狭隘部へ接近→形態を作る→LiDAR支援で通過→再変形→EEをValveへ接触→形態を選んで回転」。
高トルクになりやすい基本形状は人間が選び、ロボットが実現可能性を評価する。
optimizerによる最大トルク形態の自動選択を目的にしない。

| 分類 | 評価項目 |
|---|---|
| 操作 | 成功率、完了時間、衝突回数、モード切替数、必要な形態変更数 |
| 形状・運動 | 形状RMSE、関節角・速度RMSE、位相遅れ |
| 飛行 | 位置・姿勢RMSE、最小\(f_{min},\tau_{min}\)、推力飽和率 |
| 狭隘部 | 最小クリアランス、衝突・近接回数、LiDAR修正量 |
| 接触作業 | 接触力・トルクのピーク、Valve回転角、作業成功率 |
| 操作者 | NASA-TLX、分かりやすさ、身体負荷、装着性 |

## 力覚の追加実験

第2優先。接触力覚の実装・校正後、選定した1つの写像でHaptic ON/OFFを比較する。
写像比較と全factorialに組み合わせず、条件数と被験者負荷を抑える。
接触力ピーク、overshoot、接触タスク成功率、反応時間、NASA-TLXを評価する。

現行の壁接触シミュレーションは観測用で、接触力覚を出力しない。
準備・記録方法は[操作手順](usage.md#壁接触の観測)を参照する。

## 指標・ログの取り扱い

人体対DRAGONの正規化形状RMSE、候補と発行指令の関節差`shape_control_error`、
`shape_task`のDRAGON対目標形態の`E_s`は異なる指標として記録する。
最適化の更新周期と指令周期も分け、計算時間の平均・95パーセンタイル・最大、
入力鮮度、ゲート拒否率、timeout・failsafeを記録する。
試験姿勢、許容誤差、校正、機体・URDF、実行環境を残し、異なる条件の数値を同一の性能として比較しない。
