# Dracomancer 研究アイデアメモ

このメモは、現在の Dracomancer 実装を前提に、今後の研究方針として有望なアイデアを整理したものです。
背景・目的そのものではなく、実装済み機能から次に伸ばせる研究テーマを扱います。

## 現状との差分

現在の実装では、`startup` / `teleoperation` の2モード、ジョイスティックと背中IMUによる広域移動、腕関節からDRAGON関節への形状マッピング、Force/Torque内接半径に基づく安全スケーリングが実装されています。

一方で、以下は未実装または設計段階です。

| 項目 | 現状 | 研究アイデア |
| --- | --- | --- |
| 力覚提示 | Mk-I ではトルク ON/OFF が既定。固定アンカーからの位置目標オフセットによる近似提示を任意実装 | 接触反力だけでなく、飛行可能性の余裕を二値的な関節ロック/解放または弱い連続的な手応えとして提示し、真の連続トルク提示は Mk-II 以降の展望にする |
| Force/Torque Volume制約 | 内接半径による一様スケーリング | 姿勢空間上のvirtual fixtureとして制限する |
| 精密動作モード | 腕関節からDRAGON関節への直接写像 | 直接写像とタスク方向射影型写像を比較する |
| 広域移動モード | ジョイスティック + IMU相対yawが既定 | 操縦座標系の違いを被験者実験で比較する |
| Mk-IIハードウェア | Mk-Iプロトタイプ | 力覚提示に必要な関節トルク・可動域・装着負担から再設計する |

## 1. 安全余裕を返す力覚提示

力覚提示を、ロボットが接触したときの反力提示だけに限定しない。
DRAGONのForce/Torque内接半径が小さくなったとき、Mk-I では Dracomancer側の対応関節サーボをトルク ON/OFF で切り替え、操作者に「その姿勢は飛行可能性を削っている」と知らせる。XL430-W250-T では個々のサーボへ所望トルクを入力できないため、真の連続的な抵抗トルク提示は Mk-II 以降の展望とする。一方で、提示トルク相当量を固定アンカーからの小さな位置目標オフセットへ変換し、高周期の短いON/OFFパルスとして出す近似提示は Mk-I でも任意に使える。

考え方:

```text
safety_margin = min(force_margin, torque_margin)
tau_equiv = K(q) * (1 - safety_margin) * direction_to_safe_pose
torque_enable_i = 1 if |tau_equiv_i| >= tau_on_threshold else 0
q_goal_i = q_anchor_i + clamp(tau_equiv_i * offset_per_nm, -max_offset, max_offset)
```

期待できる主張:

- Mk-I では操作者は危険姿勢へ入る前に、連続的な力ではなく関節の保持/解放として安全境界を知覚する。
- 形状安全スケーリングと力覚提示を同じ安全指標で統一できる。
- サーボモータは単なる角度取得ではなく、Mk-I では二値的な警告提示、Mk-II 以降では連続トルク提示として、操縦意図と飛行可能性をつなぐ双方向インタフェースになる。

ハードウェア設計との関係:

- 全7関節に強い力を返す必要はない。
- 肩・肘など知覚しやすく大きなトルクが必要な関節を重点的に強化し、手首は軽い警告提示または角度取得中心にする設計が現実的。
- Mk-IIでは、電流制御またはトルク制御に対応するアクチュエータを候補に入れ、各関節の最大提示トルク、バックドライバビリティ、非常停止時の脱力挙動を設計要件に入れる。

関連研究:

- Haptic shared autonomyでは、安全制約によって修正された操作者入力との差分を力覚として返す。Dracomancerでは、この考え方を多関節飛行ロボットの形状安全へ拡張できる。DOI: `10.1109/ICRA48506.2021.9560991`

## 2. Virtual fixture型の精密動作モード

現在の `precision` モードは、Dracomancerの腕関節をDRAGONの関節へ直接マッピングする。
比較対象として、作業に有効な方向だけを通し、危険または不要な方向を柔らかく抑制するvirtual fixture型のマッピングを導入する。

単純な定式化:

```text
q_raw = M(q_human - q_neutral) + q_offset
q_cmd = q_safe + alpha * P_task * (q_raw - q_safe)
```

ここで、`P_task` は作業方向または許容姿勢空間への射影、`alpha` はForce/Torque内接半径から決める安全ゲインとする。

比較実験の候補:

| 条件 | 内容 |
| --- | --- |
| Direct mapping | 現在の腕関節からDRAGON関節への直接写像 |
| Safety scaling | 現在の内接半径ベースの一様スケーリング |
| Virtual fixture | タスク方向を優先し、危険方向を抑制する写像 |

評価指標:

- 接触作業の成功率
- 作業時間
- 姿勢安全余裕の最小値
- 不可能姿勢への進入回数
- NASA-TLXなどの主観的負荷

関連研究:

- Virtual fixtureは、操作者の入力を望ましい方向へ導き、望ましくない方向を制限する遠隔操作支援として使われてきた。DOI: `10.1109/ROBOT.2003.1241880`

## 3. ジョイスティック + 背中IMUの操縦座標系評価

`wide` モードでは、ジョイスティック入力を背中IMUの相対姿勢に基づいて移動方向へ変換している。
これは装着型デバイスならではの特徴なので、単なる実装機能ではなく研究評価対象にできる。

比較条件:

| 条件 | 内容 | 仮説 |
| --- | --- | --- |
| `direction_mode=none` | world座標で移動 | 実装は単純だが、操作者の身体方向とずれやすい |
| `direction_mode=yaw` | 背中IMUの相対yawで水平移動を回転 | 直感性と安定性のバランスが良い |
| `direction_mode=yaw_pitch` | 相対yawとpitchを反映 | 前傾意図を使えるが、誤入力が増える可能性がある |
| `direction_mode=full` | 3D相対姿勢を反映 | 実験的。習熟負荷が高い可能性がある |

評価指標:

- 目標地点到達時間
- 経路長と軌道逸脱量
- 入力反転や停止操作の回数
- 操作者の主観的な直感性
- IMU yawドリフトに対する再キャプチャ頻度

## 4. 立ち上げ時のモード設計

DRAGONは離陸時に通常姿勢または円形に近い姿勢を保つ必要があり、人間の腕形状をそのまま写すことはできない。
現状の `startup_pose` 保持を、研究上は「人間形状写像を一時的に切り離す安全起動モード」として整理する。

発展案:

- `startup`: ロボット側の安定離陸姿勢を優先する。
- `arm_sync`: ホバリング後にDracomancerの中立姿勢を再取得する。
- `precision`: 中立姿勢からの相対変位をDRAGON形状に反映する。

この遷移により、離陸時の安全性と精密操作時の直感性を両立しやすくなる。

## 5. Mk-IIハードウェアへの設計要求

Mk-IIでは、単にリンク長や干渉部を修正するだけでなく、力覚提示と長時間装着を前提に設計要求を整理する。

候補:

- 肩・肘関節は、Mk-I のトルク ON/OFF から Mk-II の連続トルク提示へ発展させる優先対象にする。
- 手首関節は軽量性と可動域を優先し、強い力覚提示の対象から外す可能性を検討する。
- インデックスプランジャによるリンク長調整は、操作者の関節中心合わせを短時間で再現するための機構として位置づける。
- サーボ脱力時に装着者の腕を拘束しすぎないよう、機械的ストッパとソフトウェアリミットを分けて設計する。
- 背中IMUは操縦座標系の基準になるため、取付角の再現性と再キャプチャ操作のしやすさを重視する。

## 優先度

短期的には、既存実装を大きく変えずに研究価値を出せる順に進める。

1. `wide` モードの操縦座標系比較
2. `precision` モードの直接写像と安全スケーリングの評価
3. 安全余裕を用いたトルク ON/OFF 型力覚提示の最小実装
4. virtual fixture型マッピングの追加
5. Mk-IIハードウェア設計への反映

最初の実験では、シミュレーション上で `direction_mode` と `enable_shape_safety` の条件比較を行い、作業時間・安全余裕・主観負荷を記録するのが最も小さく始められる。
